# Human Atlas 交互优化方案

> 日期:2026-09-09 · 依据:代码走查 + 桌面/移动实测 · 配套:[PRD.md](PRD.md) · [TECH-PLAN.md](TECH-PLAN.md)
> 与 MuscleMap 里程碑(M0–M6)重合的项在表中注明,只做一次。

## 一、问题与方案总表

### 1. 布局与能力聚焦(核心方向:肌肉 + 训练)

| 做什么操作 | 交互哪里不方便 | 解决方案 |
| --- | --- | --- |
| 进入首页 | 默认 14 个系统全开,首屏是"解剖全家福",肌肉淹没在血管神经中;搜索建议词全是内脏(heart/brain/liver) | 默认视图改为「肌肉+骨骼」;搜索建议换高频肌肉(胸大肌、肱二头肌、股四头肌等);默认索引聚焦肌肉概念,「显示全部结构」开关收纳其余(PRD F0/F1) |
| 只看肌肉 | 「只看肌肉」只是三个小预设按钮之一;15 个系统开关全部展开占满左栏,与核心能力平权 | 图层面板顶部改为三档主预设「只看肌肉 / 肌肉+骨骼 / 全部解剖」占主位;15 系统细分默认折叠为「系统细分 ▾」,两次点击内可达 |
| 边看训练信息边操作 3D | 详情是临时弹出的右侧 Sheet:打开时视角按钮被隐藏,768–1100px 时左侧图层面板直接消失;视角、爆炸滑杆散落在右侧中部和底部中央 | 布局改为**双态切换**:未选中 = 3D 占满全屏(纯观赏);选中 = 右栏滑入成左右结构(左区=3D+全部 3D 操作,右栏=训练信息)。视角/爆炸/旋转/重置归并为一条 3D 工具条置于左区底部,不再因右栏出现而隐藏;取消选中即回到全屏,切换带平滑过渡 |
| 未选中结构时浏览身体 | 右侧空白,无内容也无用途;若设常驻右栏则白白挤占 3D 观赏空间 | 不设常驻右栏:未选中时 3D 占满全屏沉浸观赏,界面元素收敛到最小;精选肌群入口/最近查看移入搜索面板空态 |
| 使用顶栏 | 大标题占据左上大量垂直空间;搜索藏在右上角小按钮里 | 顶栏紧凑化:标题缩小,搜索框升为顶栏主位 |
| 首次访问 | 700ms 后自动弹出「关于」Sheet 打断主任务;关于页内嵌 X/Twitter 时间线(外部脚本,加载不稳) | 删除自动弹窗与 X 时间线(保留文字链);改为一次性 3 步引导(点肌肉 → 看动作 → 拖滑杆) |
| 日常使用 | 底部「拖拽旋转 · 双指缩放 · 点按查看」常驻,信息价值衰减 | 首次显示,3 次交互后淡出 |

### 2. 搜索与选中

| 做什么操作 | 交互哪里不方便 | 解决方案 |
| --- | --- | --- |
| 搜索常用肌肉名 | BodyParts3D 概念粒度到左右侧/亚区:搜「腹直肌」0 结果(数据无此概念),「肱二头肌」只有短头/长头子结构,「胸大肌」12 条结果无主概念 | 建「常用名 → 概念聚合」映射表(先覆盖健身 TOP 100 肌肉):`肱二头肌 → 左/右短头+长头`;命中聚合名置顶并合并高亮全部成员。与 M1 肌肉注册表同源,注册表提前产出此表 |
| 搜索无结果时 | 只显示「没有找到结果」,而数据里其实有「腹肌」等上位分组概念 | 空态展示:近似/上位分组概念(可点击)+ 示例搜索词 + 一键清空 |
| 浏览搜索结果 | 左右/子结构混排,「胸大肌带区」排在「左/右胸大肌」之前 | 排序分层:主概念 > 分组概念 > 左右侧 > 亚区;同权重按部件数降序 |
| 输入拼音 | 仅中英文精确子串匹配,拼音无响应 | 接入拼音全拼/首字母匹配(依赖 M1 索引,TECH-PLAN §3.3) |

### 3. 肌肉详情与训练动作(右栏)

| 做什么操作 | 交互哪里不方便 | 解决方案 |
| --- | --- | --- |
| 打开任一肌肉详情 | 首次打开同步拉取 3.5MB `exercise-index.json`,有明显等待 | 模型加载完成后 `requestIdleCallback` 预取;确认生产环境 Brotli/Gzip 生效(压缩后预计 < 1MB);长期按粗分组拆分索引 |
| 浏览训练动作列表 | 单块肌肉 200–270 条动作一次性渲染(实测腹外斜肌 271 条、约 2,370 个 DOM 节点),定位困难 | 初始 20 条 + 「显示更多」/滚动触底加载 |
| 筛选动作 | 只有「仅主动肌」一个开关,271 条无从下手 | 器械 chips 筛选(`equipment` 字段与中文映射已有)+「主动肌优先」排序 |
| 阅读肌肉说明 | 个体说明缺失,回退为肌肉系统通用文案(如腹外斜肌显示"骨骼肌通过牵拉附着点产生运动…") | 先为 TOP 30 常练肌肉补个体文案(起止点/功能/训练要点),后续并入 M2 说明卡;回退态的提示文案前移到描述上方 |
| 观看动作动画 | GIF 不可暂停/倍速;加载慢时空白,失败破版 | 骨架屏占位 + `onError` 降级;放大态支持暂停/0.5×/1×(PRD F5) |
| 复制 FMA 编号 | 编号为纯文本不可复制 | 一键复制 + toast |

### 4. 3D 场景操作

| 做什么操作 | 交互哪里不方便 | 解决方案 |
| --- | --- | --- |
| 在密集场景定位选中结构 | 选中只变青色,爆炸总览(2,229 件)中肉眼难辨 | 选中叠加描边或呼吸动画(shader per-part 通道已有,扩展成本低);爆炸总览态给选中格加药丸标签 |
| 从爆炸 100% 退出 | 视角按钮全部禁用、旋转禁用,只能手动把滑杆拖回 0 | 爆炸态常驻「收拢」按钮 + 双击空白复位 |
| 点选深层肌肉 | 皮肤只有显隐开关,必须先关掉浅层系统才能点到深层 | 皮肤透明度滑杆(PRD F0);或按住 Alt 点击 = 穿透选次近结构 |
| 爆炸态点击/悬停小部件 | 鼠标命中半径仅 16px;悬停提示只有名称 | 命中半径提到 20–24px;提示加系统色点 + 部件数 |
| 回访找上次看过的肌肉 | 每次进入均为初始状态 | localStorage 记录最近 5 次选中,在搜索面板空态展示(与精选肌群入口同处) |

### 5. 移动端(布局重构对移动端不做结构性改动,以下为独立问题)

| 做什么操作 | 交互哪里不方便 | 解决方案 |
| --- | --- | --- |
| 查看肌肉详情 | 底部 dock(约 139px)与面板挤压 3D 可视区,隔离态模型仅剩约 1/3 屏;一次实测面板高度溢出几乎全屏(未复现) | 详情面板顶部加拖拽把手:半屏 ↔ 全屏 ↔ 关闭三档;隔离态默认收窄;真机复核溢出问题 |
| 爆炸总览点选部件 | 2,200+ 小格过密,单个格子仅几像素,几乎不可点 | 爆炸 > 80% 时提示「用搜索定位」;或按系统过滤后再爆炸(与三档预设联动) |
| 打开搜索/系统面板 | 两个面板可同屏叠放,互相遮挡 | 打开任一面板时自动关闭另一个 |

## 二、总体规划

### 1. 改动分组(同类型归组)

| 组 | 类型 | 包含项 | 特点 |
| --- | --- | --- | --- |
| **A. 数据与内容** | 数据生产 | 聚合映射表、拼音索引、TOP 30 个体说明 | 最底层:搜索与说明的地基;性质是数据工程,可与前端改造并行;与 M1/M2 同源 |
| **B. 布局骨架** | 结构改造 | 双态布局(未选中 3D 全屏 ↔ 选中后右栏滑入)、3D 工具条归并、顶栏紧凑、小屏(≤1100px)右栏退化为可开合抽屉 | 底层:改变页面骨架;动作筛选落点、移动端把手等后续改动都挂在其上;改造量最大 |
| **C. 肌肉优先默认态** | 配置与呈现 | 默认视图肌肉+骨骼、三档主预设、系统细分折叠、搜索建议肌肉化 | 轻量:基本不动结构,可独立发布、立即见效 |
| **D. 规模与性能** | 加载策略 | 索引预取、动作列表分页、生产压缩确认、图片占位/降级、器械筛选 | 独立:不依赖布局;但右栏形态落定后分页与筛选的落点更自然 |
| **E. 3D 交互增强** | 效果与反馈 | 选中描边、爆炸收拢、皮肤透明度、tooltip 增强、最近查看 | 在既有结构上叠加,不改动骨架 |
| **F. 移动端专项** | 平台适配 | 面板把手、溢出复核、面板互斥、爆炸定位引导 | 依赖 B 落定后的最终面板形态 |
| **G. 清理减法** | 删除项 | X 时间线、首访自动弹关于、常驻操作提示、FMA 复制 | 随时可做,零风险 |

### 2. 实施顺序(底层先行)

```
阶段 1  C + G   肌肉优先默认态 + 清理     ──┐
阶段 2  B      布局骨架重构               ──┼── 互相独立,可同时启动
并行轨  A      数据与内容(对接 M1/M2)    ──┘
                 │
                 ▼
阶段 3  D      规模与性能(挂到右栏常驻结构上)
                 │
                 ▼
阶段 4  E + F  3D 交互增强 + 移动端专项
```

| 阶段 | 组 | 前置依赖 | 预估 |
| --- | --- | --- | --- |
| 1 | C + G | 无 | 约 1 周,先行发布、立即体现聚焦 |
| 2 | B | 无(与阶段 1 独立) | 约 1.5–2 周,最大单项;含小屏抽屉退化方案 |
| 并行 | A | 无(数据生产) | 与 M1/M2 协同,不阻塞前端 |
| 3 | D | 阶段 2(预取绑定右栏、分页落位) | 约 1 周 |
| 4 | E + F | 阶段 2 | 约 1.5 周 |

### 3. 关键依赖说明

- **A 是搜索三项(聚合/空态/拼音)的前置**:没有映射表,空态兜底与聚合高亮都无数据可用;A 建议按 M1 注册表 schema 起草,字段直接兼容,未来并入不返工。
- **B 是器械筛选落点、移动端把手的前置**:面板形态未定前做这两项会二次返工。
- **C 与 G 完全独立且零风险**:不等 B,可立即做、立即发版。
- **D 的「确认生产压缩」不依赖任何阶段**,随时可查。
- B 的主要风险:布局切换的相机适配——`scene.tsx` 的 `fit()` 需支持双态(未选中 = 全屏构图,选中 = 预留右栏 340–420px,isolate 避让已有现成分支),切换时相机平滑 re-fit 而非跳变;右栏挤压小屏 3D 空间时,≤1100px 退化为可开合抽屉(默认收起、带徽标),不回到"面板互斥隐藏"的老问题。
