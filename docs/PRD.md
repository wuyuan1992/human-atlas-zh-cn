# 肌图 MuscleMap — 产品需求文档(PRD)

> 项目代号「肌图 MuscleMap」为暂定名,可随时更换。
> 本项目以本仓库(human-atlas)的 3D 解剖浏览器为基座二次开发。
> 版本:v0.1(立项稿) · 日期:2026-09-07

---

## 1. 项目背景与定位

human-atlas 已经实现了一个可在浏览器流畅运行的 3D 人体解剖浏览器:2,234 个可独立选中的网格、15 个系统分层、概念搜索与选中联动。但它是一个「解剖参考工具」——只回答"这是什么、在哪"。

肌图 MuscleMap 在同一具 3D 身体上回答健身用户真正关心的问题:**"这块肌肉叫什么、怎么练、我练的这个方案到底练到了哪"**。产品定位是:

- **面向中文健身人群的交互式 3D 肌肉地图 + 训练方案助手**;
- 以 3D 模型为核心导航界面(而非文字列表),点哪块肌肉、聊哪块肌肉;
- 教育与参考属性,**不是医疗或康复诊断工具**。

一句话描述:**在真三维的人身上选中任意一块肌肉,立刻看到中文说明、拿到训练方案、看到动作动画,再把整个方案影响的肌肉群亮回身体上。**

## 2. 目标用户与核心场景

| 用户 | 画像 | 典型场景 |
| --- | --- | --- |
| 健身爱好者 | 训练 0–3 年,知道"胸背腿"粗分,说不清具体肌肉 | "教练让我练'肩后束',到底在哪?顺便教我怎么练" |
| 私教 / 健身自媒体 | 需要向会员直观展示目标肌群与动作原理 | 备课讲解"卧推不只练胸",逐块点亮协同肌 |
| 运动康复 / 运动人体科学学习者 | 需要肌肉起止点、神经支配等结构化知识 | 复习"冈上肌"的起止点与功能,配合 3D 定位记忆 |
| 医学生 / 解剖入门者 | 中文学习者,需要中英对照 | 用"腹直肌 / rectus abdominis"双语检索并对照 3D |

核心使用闭环(产品主流程):

```
搜索(中/英)或 3D 点击 选中一块肌肉
        ↓
中文说明卡(是什么、起止点、功能)
        ↓
「为我推荐训练方案」→ 动作列表(含动画、组次)
        ↓
「这套方案练到了哪」→ 全身相关肌肉群按角色点亮
        ↓
点击任意被点亮的肌肉 / 结果里的肌肉标签 → 再次选中,进入下一轮循环
```

这个闭环是产品的心脏:**从肌肉到方案,再从方案回到肌肉**,可以无限循环探索。

## 3. 术语表

| 术语 | 定义 |
| --- | --- |
| 部件(Part) | 3D 模型中一个可独立选中的网格,源自身里的 2,234 个 mesh |
| 概念(Concept) | 具名解剖结构,持有 FMA 编号(如 `FMA9629` 冈上肌),可含多个部件 |
| 肌肉注册表(Muscle Registry) | 本项目新建的权威肌肉清单:概念 ID + 中文名 + 英文名 + 拼音 + 别名 + 粗分组 + 训练属性,是搜索、说明、AI 校验共用的单一事实源 |
| 粗分组(Coarse Group) | 健身语境的肌群分类(胸 / 背 / 肩 / 肱二头 / 股四头……),用于桥接动作库与具体肌肉概念 |
| 动作库(Exercise Library) | 开源动作数据集的本地化副本,含动画、步骤、目标肌群字段 |
| 方案(Plan) | 针对某肌肉/目标生成的一组动作(名称、组次、负荷建议) |
| 肌肉角色(Role) | 方案中肌肉的参与方式:主动肌 prime / 协同肌 synergist / 稳定肌 stabilizer / 拮抗肌 antagonist |
| 反推(Reverse lookup) | 由方案聚合出其影响的全部肌肉群,并按角色在 3D 上分层点亮 |

## 4. 需求范围与优先级

用户原始需求编号从 2 开始,推定需求 1 为"以 3D 人体模型为基础浏览界面"(即现有仓库能力),在此一并列为 F0。

| 编号 | 需求 | 优先级 | 对应功能 |
| --- | --- | --- | --- |
| F0 | 3D 人体肌肉浏览基础(继承现仓库:旋转/缩放/分层/点击选中/移动端适配) | P0 | 现有能力 + 肌肉优先改造 |
| F1(原 2) | 名称搜索(中英文)与 3D 点击,两种方式选中任意肌肉 | P0 | 双通道选中 |
| F2(原 3) | 对任意肌肉展示中文说明 | P0 | 中文肌肉说明卡 |
| F3(原 4) | 对任意肌肉推荐训练方案(可借助实时 AI) | P0 | 方案推荐 |
| F4(原 5) | 倒推任意方案影响的全部肌肉群(可借助实时 AI;结果标注肌肉关键信息,可点击选中) | P0 | 方案反推点亮 |
| F5(原 6) | 推荐动作的训练动画(开源 GitHub 仓库) | P1 | 动作动画 |

### 4.1 F0 — 3D 肌肉浏览基础

现仓库已具备的能力全部继承:OrbitControls 漫游、系统分层开关、爆炸视图、隔离选中结构、预设机位、移动端布局。改造点:

- 默认视图改为**肌肉优先**:默认可见系统 = 肌肉 + 骨骼(保留骨骼作空间参照),皮肤以半透明开关提供(默认关),其余系统收纳进面板不默认显示;
- 首屏文案、示例搜索词改为肌肉语境(如"胸大肌、冈上肌、肱二头肌");
- 保留全量解剖数据(不删模型),只是默认呈现方式变化——满足"任意肌肉"都可选中的要求。

### 4.2 F1 — 双通道选中(搜索 / 3D)

**搜索通道:**

- 支持简体中文、英文、拼音全拼、拼音首字母、常见别名的混合检索:输入"胸大肌""pectoralis""xiongdaji""xdj""卧推肌"均能命中;
- 搜索结果展示:中文名 + 英文名 + 所属粗分组 + 该概念包含的网格数;
- 键盘 `/` 聚焦(继承现有快捷键),↑↓ 选择,回车选中;
- 仅可训练的骨骼肌概念进入默认索引(约 300+ 条目);其余概念(血管神经内脏)可通过开关"显示全部结构"纳入,保证"任意肌肉"都能搜到——肌肉本身全部可搜。

**3D 通道:**

- 继承现有射线拾取:点击身体上任意可见网格即选中其所属概念;
- 针对"肌肉被皮肤遮挡"的场景:提供皮肤透明度滑杆;隐藏皮肤时深层肌肉直接可点;
- 悬停提示(hover tooltip)中英双语显示;
- 选中反馈继承现有高亮机制,并新增:选中肌肉时镜头自动微调使其不被完全遮挡(利用现有 isolate 相机逻辑的轻量版)。

**验收标准:** 对注册表内全部肌肉概念,中文名、英文名、拼音全拼、首字母四种输入均可在结果前 5 位命中;3D 点击在皮肤关闭/半透明/打开三种状态下均可选中浅层与深层肌肉;两种通道最终都打开同一张肌肉说明卡。

### 4.3 F2 — 中文肌肉说明卡

选中肌肉后,在右侧(移动端为底部)详情面板展示结构化中文说明:

| 字段 | 内容 | 来源策略 |
| --- | --- | --- |
| 标题 | 中文名 + 英文名 + FMA 编号 | 注册表 |
| 概览 | 2–3 句通俗说明(这块肌肉在哪、干嘛的) | 中文维基/权威资料优先,AI 起草 + 人工审校 |
| 起点 / 止点 | 解剖学标准描述 | 同上 |
| 神经支配 | 支配神经 | 同上 |
| 主要功能 | 动作列表(如肩外展) | 同上 |
| 训练要点 | 3–5 条该肌训练注意事项 | 同上 |
| 常用训练动作 | 该肌的代表动作快捷入口(点击直接看动画) | 动作库映射 |

- 非肌肉概念被选中时,降级显示现有系统级说明(继承 `explanation()` 的回退逻辑);
- 面板内保留"隔离显示""查看解剖源(FMA/lifesciencedb 链接)"等现有操作;
- 内容全部本地化打包(不走实时 AI),保证离线可用与加载速度;
- 每张卡片底部固定免责声明:内容仅供学习参考,不构成医疗建议。

**验收标准:** 注册表内全部肌肉均有非空的中文名、概览、功能、训练要点;起止点/神经支配允许少量标记为"整理中";字段错误(串卡、张冠李戴)在验收阶段为零。

### 4.4 F3 — 训练方案推荐

在肌肉说明卡内提供主操作按钮**「推荐训练方案」**:

- 可选参数(折叠,默认智能推断):目标(力量/肥大/耐力/激活)、器械条件(徒手/哑铃/杠铃/弹力带/健身房)、水平(初/中/高);
- 方案为结构化卡片列表:动作名(中英)、对应动画、组 × 次数、组间休息、负重建议、动作要点;
- 每个动作卡片标注**目标肌肉标签**(中文),标签可点击 → 直接选中该肌肉并打开其说明卡(与 F5 的点击联动要求一致);
- 生成方式两级:
  - **在线(AI)**:实时查询,生成个性化方案(详见技术方案);结果必须通过注册表校验——AI 返回的每个肌肉引用都带概念 ID,未通过校验的条目被剔除或纠正;
  - **离线(内置)**:AI 不可用或未配置时,回退到内置精选方案库(由开源动作数据预先编排,如"胸部徒手入门 4 动作"),同样带肌肉标签与反推能力;
- 方案支持"换一批"与参数重选;
- 免责与安全提示:页面常驻"训练建议仅供参考,如有伤病请咨询专业人士"。

**验收标准:** 任选 30 块主流肌肉生成方案,返回动作均存在于动作库或经动画/图片兜底;肌肉标签 100% 可点击且命中注册表;AI 服务中断时离线方案无感接管;平均生成耗时在线 ≤ 8 秒(含流式首字 ≤ 3 秒)。

### 4.5 F4 — 方案反推:点亮全部影响肌肉群

方案(在线或离线)展示区提供**「这套方案练到哪」**开关,开启后:

- 3D 模型上按**角色分层点亮**该方案涉及的全部肌肉:主动肌(高饱和主色)、协同肌(次级色)、稳定肌(弱色)、拮抗肌(轮廓色);未涉及的肌肉压暗;
- 角色图例常驻,可单独开关每类角色的显示,便于"只看主动肌"式聚焦;
- 每个角色分组配一个**肌肉标签列表**:中文名 + 英文名,点击任意标签 → 该肌肉高亮选中 + 打开说明卡,进入下一轮探索(主循环闭环);
- 非肌肉结构(骨、皮肤)可切换为"只留骨骼参照"或全部隐藏,避免视觉干扰;
- 反推来源:动作库自带的目标肌群字段(离线可靠)+ AI 补充的精细角色标注(在线增强,如"卧推中前锯肌为稳定肌"),AI 标注同样过注册表校验;
- 点亮状态与爆炸视图兼容:爆炸时标签仍指向对应网格。

**验收标准:** 任意内置方案与在线方案均可反推;点亮肌肉数 ≥ 该方案动作库标注肌肉数(允许 AI 增补协同/稳定肌);所有角色标签可点击且能正确选中 3D 对应概念;角色颜色在亮/暗背景下可区分(通过对比度检查)。

### 4.6 F5 — 训练动画

- 方案与说明卡中的每个动作,优先展示**动图/动画演示**;
- 数据源采用开源 GitHub 仓库(许可与选型详见技术方案 §2.3,产品侧约束如下):
  - 动画必须可随仓库一起再分发,或可稳定外链;
  - 必须保留数据集要求的署名(页脚统一署名区);
  - 无动画可用的动作允许降级为静态图(双图),再降级为无图;
- 播放交互:点击放大、循环播放、倍速(0.5×/1×)、暂停逐帧;
- 移动端默认 lazy-load,进入视口才拉取,列表滚动不卡顿;
- 动画卡片附带:难度、器械要求、中文步骤要点(可展开)。

**验收标准:** 主流 100 个动作中动画覆盖率 ≥ 90%;移动端 3G 慢网下列表滚动可交互;署名信息在关于页与页脚完整展示。

## 5. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏可交互(不含肌肉数据)≤ 3s(桌面宽带);模型渐进加载继承现有分块机制;动画 lazy-load |
| 兼容 | 继承现仓库:主流桌面/移动浏览器,WebGL 必须;390×844 等手机布局已验证的交互不回退 |
| 可用性 | 离线模式下 F1/F2/F5 与离线版 F3/F4 完整可用;仅 AI 增强部分依赖网络 |
| 隐私 | 不建账号、不收集个人数据;AI 查询仅携带肌肉 ID 与参数,不携带任何用户身份信息 |
| 合规 | 训练/解剖内容双免责声明;数据许可署名完整(见 §7);AI 输出标注"AI 生成,已校验/未校验"状态 |
| 可维护 | 数据(注册表/动作库/说明内容)与代码分离,全部走构建脚本可再生、可校验 |

## 6. 明确不做(Non-goals,v1)

- 训练记录、打卡、日程、社交、饮食管理;
- 用户账号体系与云端同步;
- 女性模型(现仓库数据为男性参考解剖;女性参考解剖的引入列为 v2 候选);
- 疼痛/伤病诊断、康复处方;
- 视频课程、付费内容;
- 训练负荷的精确周期化编程(仅提供单次方案级建议)。

## 8. 成功指标(上线后 3 个月)

- 搜索 → 选中成功率(搜了且点了结果)≥ 60%;
- 选中肌肉 → 打开方案 的转化 ≥ 40%;
- 方案反推点亮功能使用率(打开方案的会话中)≥ 50%;
- AI 输出肌肉校验通过率 ≥ 95%(低于此值说明注册表或提示词需返工);
- 动画加载成功率 ≥ 97%;
- 移动端占比预期 > 60%,以移动端留存(7 日回访 ≥ 15%)为核心北极星。

## 10. 开放问题

1. 产品名与视觉风格(现仓库为英文"studio"风格,新项目需中文优先的视觉定义);
2. 是否在 v1 提供 WebMCP 工具的中文版(现仓库已有 `find_anatomy`/`inspect_anatomical_structure` 模式可扩展为 `recommend_plan` 等);
3. AI 服务的部署与费用策略(免费限额、BYOK 自带密钥模式是否开放);
4. 动作数据集的媒体条款商用复核结论(影响默认动画源选择)。
